## 二、后端接口（唯一正确来源）

**用 `/api/leave/overview?year=2026`**（`leave.js` 第 2387 行）
⚠️ 不是 `/api/leave/all` —— 那是另一套口径，剩余算得不对。

### 返回结构

```json
{
  "year": 2026,
  "available_years": [2026, 2027],
  "headcount": 30,
  "cp_excluded": 11,
  "summary": { "total": 285, "used": 253, "left": 35, "pending": 0 },
  "people": [{
    "staff_id": "19993", "name": "余建东", "seq": 15,
    "is_leader": false, "is_instructor": true,
    "total": 5, "used": 5, "left": 0, "pending": 0,
    "by_type": [{ "name": "年休", "total": 5, "used": 5, "left": 0, "over": false }]
  }],
  "cp_people": [ ... 同结构，无 is_leader/is_instructor ... ]
}
```

### 关键口径（代码注释 2308-2311 行，必须遵守）

> 剩余合计**只能用「各假别正剩余」相加**，不能让一个假别超支吃掉别的假别。
> 反例：韩思成年休已休5.5、育儿假剩5 → 25-25.5=-0.5 → 显示"已用完"，
> 但他实际还有 5 天育儿假可以休。超支是年休的事，不该连累育儿假。

即 `left = Σ max(0, 各假别 total - used)`，**不是** `Σtotal - Σused`。

### 其他口径

- **已休** = `status IN ('verified','locked','reported','released')`；作废/驳回不算
- **批准了就算扣**（不管休没休到）；`submitted` 不算已休，算 `pending`（待批）
- **超支显示**：`total > 0 && used > total` → `8/5（超3）`，**不要 ⚠ 图标**
- **额度为 0 且已休 > 0** → `已休N 已用完`，这是管理员主动置 0 的正常状态，**不算超支、不标告警**
- **车峰不计入**在编 30 人合计，单独列出做差异标注

## 三、界面结构（从上到下）

### 1. 标题栏（折叠状态也显示）

```
▾ 全组休假总览   30人 · 剩 35 / 285天
```

默认**折叠**（`open=false`）。折叠时只显示这一行摘要，且**不请求接口**。

### 2. 年份切换

```
[2026] [2027]
```

用 `available_years` 渲染，当前年份高亮。2026=过渡年（乘务系统统计），2027=正式年（车间统筹表为底座）。

### 3. 顶部汇总 —— **只要三列**

```
        在编 30 人合计            全组 41 人（在编 30 + 车峰 11）
┌────────────┬────────────┬────────────┐
│  假期总额   │    已休    │    剩余     │
│    285     │    253     │     35     │
└────────────┴────────────┴────────────┘
```

❌ **不要再分类展开各假别**（11-27 09:26 明确否掉）

### 4. 排序切换

```
[剩余从多到少]  [已休从少到多]
```

默认「剩余从多到少」。
（11-27 之前叫「已休从多到少」，老韩 11-27 改成「已休从少到多」——两个都试过，
最新说法是「剩余从多到少和已休从少到多」）

### 5. 在编人员列表（30 人，详细显示）

每人一条，结构：

```
1  艾凌风  组长 教员        休 29 / 35   剩6
   ███████████████████░░░░
   年休 10/10 · 陪产假 15/15 · 育儿假 4/10
```

- **序号 = 行号**（`idx + 1`），第一行 1、第二行 2，不随排序变
- 姓名后带角色标签：`组长` `教员`（来自 `is_leader` / `is_instructor`）
- 主数字 = **四项合计** `used / total` + `剩X` / `已用完` / `超X`
- 进度条颜色：蓝 `#6ba5fb`（休得少）/ 橙 `#e8a726`（休过半）/ 红 `#e8723c`（用完或超出）
- 底部小字 = **各假别明细**，只列 `total > 0 || used > 0` 的
  - 正常：`年休 7.5/10`
  - 超支：`年休 8/5（超3）` 红色
  - 额度 0：`年休 已休6 已用完`
- **点击整行 → 弹窗**

### 6. 车峰区（11 人，灰色小字，不展开明细）

```
- - - - - - - - - - - - - - - - - - - -
⚠ 以下 11 人为车峰（临时调整跑车方式，保留组籍）
不计入上方在编 30 人合计，仅作差异标注

12  朱贵璇    休 5 / 5    已用完
21  熊李洋    休 5 / 5    已用完
23  吕鑫锋    休 15 / 15  已用完
```

- 灰色小字（10.5px）
- **单行**，无进度条、无各假别明细
- 按 `seq` 排序
- 序号 = 该区的行号（同样从 1 开始）
- 措辞**只用「车峰」**，不要「编外」

## 四、点某人 → 弹窗（这个功能我漏做了大半）

### 需求（11-26 17:47 老韩原话）

> 「在总揽里，点击某个人，是不是应该弹窗显示它的休假记录？按时间线排列。
> 没有记录的就放在最下面，比如1，2，3，4:剩余1.5无相关记录。后面加个补的按钮可以编辑。
> 包括休超部分，5:休超1.5 加按钮可以编辑备注。」

### 弹窗内容

```
曹枝满                                     ✕
2026 年 · 3 条记录

[年休 4/5  剩1]
[育儿假 5/10 剩5]

年休   2026-10-28                       1天
       已核对  车间表              ＋备注

年休   2026-10-06                     0.5天
       已核对  车间表              改备注
       ┌──────────────────────────┐
       │老韩2026-11-26核定：10-06  │
       │实为0.5天（原系统记1天）    │
       └──────────────────────────┘

年休   2026-05-13 ~ 2026-05-15        2.5天
       已核对  车间表              ＋备注
```

### 要素

- **按时间线倒序**（最近在上）
- 每条显示：假别标签、日期、天数、状态、来源（`车间表` / `补录` 黄色）
- 每条有 **「＋备注」/「改备注」** 按钮 → 走 `PATCH /api/leave/:id/note`，存 `relief_note`
- **作废/驳回的记录灰色显示**（管理员要看全貌）
- **没有记录的人** → 显示「无相关记录」+ **「＋ 补录一条」按钮**
- **休超的人** → 显示「休超1.5」+ 备注按钮

### 补录表单（11-26 18:07 做过，实测通过）

```
补录一条休假记录
假别      [年休 ▾]
开始日期  [2026-12-20]
结束日期  [        ]  ← 留空=同开始
扣假天数  [1       ]  ← 支持 0.5/1/2.5
备注      [车间表漏记，与本人确认过  ]
                    [取消] [确认补录]
```

规则：
- 直接生效 `verified`，不走五步审批
- `source=supplement`，弹窗显示黄色「补录」
- 同一人+同一假别+同一开始日期+同一天数 重复提交拦截
- 写操作日志

### 数据来源

`GET /api/leave/staff/:staffId?year=2026`（`leave.js` 第 427 行）
返回：`is_cp` / `seq` / `lines[]` / `gaps[]` / `leave_options[]` / `records[]`
记录字段：`id, leave_type, start_date, end_date, days, status, source, relief_note, cancel_reason, reject_reason, created_by, created_at`
